計算量 体験ラボ

同じ数字の並びを、3つのやり方で処理します。「再生」を押して、何回の操作で終わるかを下のカウンターで比べてください。N（データの個数）を 8 → 16 → 32 と倍にしたとき、回数がどう増えるかが一番の見どころです。

いま比べている／置いている いま作業中の範囲 確定 候補から外れた

バブルソート

O(N²)

隣どうしを比べて、大きい方を右へ送る。これを1周 ≒ N 回やると一番大きい数が右端で確定する。全部確定するまで約 N 周必要なので、N × N。

見るポイント：N を 16 → 32 に倍にすると、比較回数は約4倍になる（2² = 4）。

マージソート

O(N log N)

1個ずつのかたまりから始めて、2つずつ合体していく（1個→2個→4個→8個…）。合体の段数はlog N 段、各段でN 個すべてを1回ずつ置くので、N × log N。

見るポイント：棒のすき間が「かたまりの区切り」。段が1つ進むごとにかたまりが倍になり、N = 16 なら4段（16→8→4→2→1 の4回）で終わる。

Timsort（Python の sort / sorted）

O(N log N)

① 左から見て、最初から並んでいる部分（ラン）を探す。下り坂ならひっくり返して使う。② ランが短すぎたら挿入ソートで伸ばす。③ できたランどうしをマージソートと同じように合体する。並んでいる部分が多いほど、③の合体が少なくて済む。

完成したラン（交互に色分け） いま差し込んでいる／置いている

見るポイント：「ほぼ並んでいる」と「ばらばら」で操作回数を比べてみてください。ほぼ並んでいるデータは長いランがそのまま使えるので、O(N) に近い回数で終わる。

見やすさのため簡略化しています。本物はランの最小の長さ（minrun）が 32〜64 個で、ここでは 4〜8 個に縮めています。また合体の順番は、ここでは隣どうしを順に合体していますが、本物はランの長さのバランスを見て決めます。

二分探索

O(log N)

並んだ数字から目的の数を探す。真ん中を見て「もっと右か左か」を決め、候補を毎回半分に捨てる。半分にできる回数は log N 回だけ。

見るポイント：N を倍にしても、調べる回数はたった1回しか増えない。左から順に探す（O(N)）と、最悪 N 回かかる。

N を本番サイズにすると

LeetCode の N は 10万前後が普通。1秒で約1億回（10⁸）処理できるとして、それぞれ何秒かかるかを計算します。
